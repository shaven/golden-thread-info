A plugin for Claude Code · MIT

Shared memory for Claude Code sessions, with rules that are enforced

Golden Thread keeps one Obsidian vault of plain markdown and git that every session reads from and writes back to. A small set of rules is re-asserted for every response, and replies or commands that break the critical ones are blocked.

Source on GitHub What's new in 0.21.0
User types

Tailored to your role

Pick one or more roles at install: developer, product manager, project manager, executive, leadership, operations, DBA or network administrator. Each role adds the files people in it usually keep, such as a spec stub, a roadmap, a one-page brief, an incident log or a device inventory. It also gives you 12 one-tap buttons in the gt pane. Drafts, briefs and summaries are written for your audience; agents that find and check facts are never told your role, so what is recorded as true does not change with it.

Security

A level to start, then every protection is its own switch

Your fingerprint, for the things that matter

Turn on gt unlock and the sensitive actions wait for you: using a stored credential, a gateway connection to GitHub, Jira or Microsoft 365, publishing, and any change that loosens a protection. You approve with Touch ID, Windows Hello or an authenticator code, and the approval covers that action. An agent's shell cannot do it for you.

Security level

Strict, trust local, trust network, insecure or paranoid. It decides which commands Claude may run without asking. It cuts prompts and is not a wall.

Sandbox mode

Fences Claude's shell and file tools off your vault and gt's own state; the vault is reached only through gt's queue.

Paranoid parts

OS lock on gt's code, a guard on shell writes to it, a signed manifest each hook checks, and single-use permits for up to 15 risky actions. Each part has its own switch.

Folders

Your vault and gt's own files are fenced off from Claude's shell and file tools. Folders outside your projects need your OK before they are read, and files are written only inside a git project, never to ~/.ssh, .env or .git. Locking any folder you choose is coming soon.

Individual guards

Protected paths, the commit test gate, push and commit fingerprints, and limits on the file and network brokers.

Change any of them with /gt:gt-settings <name> <value>. With gt unlock on, loosening one needs you present, so an agent cannot do it on its own.

Compared with

Why Golden Thread

vs. a CLAUDE.md file

A rules file is read once and drifts out of attention in a long session. Golden Thread re-injects its Core rules on every turn and blocks the breaks of the critical ones.

vs. a memory database

Memory is plain markdown in git: you can read it, diff it, fix a wrong fact and retract it everywhere it was repeated.

vs. skipping permissions

Skip-permissions is all or nothing. Here you pick a level, then turn each protection on or off by itself.

vs. cloud memory

Your vault stays on your machine, in your own git, and opens in Obsidian like any other notes.

vs. many MCP connections

LOTR puts one gateway in front of your MCP servers, so tool schemas and large results stay out of your main context.

Coming in 0.21.0

What's new

Security level at install

The installer asks every choice up front, security first. Five levels, from strict to paranoid, decide how much Claude may run without asking. They reduce prompts; they are not a security boundary.

Paranoid

Strict plus locks on gt's installed code: read-only files, a guard on shell writes, and a signed manifest each hook checks before it runs. Changing it needs you in person.

Single-use permits

Optional tokens for 15 risky actions, including push, publish, file writes and network fetches. Bound to one action and target, they expire in minutes and work once.

File and network brokers

Disk reads, web fetches and file writes each go through one narrow agent. Paths like ~/.ssh, .env and .git are never written, even with approval.

Spend less allowance

One token profile sets seven cost settings. A cache-expiry guard compacts idle sessions while their cache is warm, and a models page shows each agent's cost.

Memory you can correct

/gt:gt-forget retracts every note that states a wrong fact. Handoffs close only when each open item is resolved.

Breaking: /gt:gt-close now closes the session and /gt:gt-complete completes a project, task or handoff. The levels very secure, mostly secure and partly secure are renamed strict, trust local and trust network; an existing setting carries over. Full list in the changelog.

The Core tier

The ten rules

1Write to the vault only through a queue, never straight into a file another session is editing.checked
2Name the vault on every command that changes it.checked
3Never put a secret's value into the session, not even to check or redact it.checked
4Never commit code whose tests you have not seen pass, and say which ran.checked
5Begin every reply with the real wall-clock time from a hook.checked
6The always-loaded memory holds only facts every project needs.reminder
7Don't load the whole memory index up front; look things up.reminder
8Run independent work in parallel, within one budget shared by every session.reminder
9Secrets live only in the secrets store, never in source, a repo, a log or a session.reminder
10Label every figure presented as fact: unverified, self-verified or independently verified.reminder

Every rule is re-asserted for every response; "checked" rules are also verified, and a reply or command that breaks one is blocked. LOTR figures are the author's own measurements; savings depend on your servers and workload.
