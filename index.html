Golden Thread 0.21.0 · a plugin for Claude Code · MIT

Shared memory for Claude Code sessions, with rules that hooks enforce

Golden Thread keeps one Obsidian vault of plain markdown and git that every Claude Code session reads from and writes back to. A small set of rules is re-injected on every turn, and hooks check the ones that must not break. This page explains how it works and what changed in 0.21.0.

The idea

"In context" is not "applied"

A rule can sit in a loaded file for a whole session and still get dropped for dozens of turns. Nothing deleted it; whatever is on screen right now crowds it out. So a rule is only as durable as the thing that re-asserts it.

Golden Thread keeps a small Core tier. Every rule is injected on every turn, in every project. The ones that must never break are also validated: a hook reads the finished reply, or the tool call about to run, and blocks it.

9Secrets live only in the secrets store, never in source, a repo, a log or a session.reminder

You can add your own, and the tier stays small on purpose: every rule added dilutes the rest.

Coming in 0.21.0

What's new in 0.21.0

You choose the security level at install

The installer now asks every choice up front, security first, in plain language. If Claude runs the install for you, it asks you each question; an install with no answer to a security question stops before anything is installed.

Five levels: strict (the default), trust local, trust network, insecure, and paranoid. They decide how much Claude may run without asking. They reduce prompts and are not a security boundary.

Paranoid: gt's own code is locked

Paranoid is strict plus locks on gt's installed code. The OS marks hooks and plugin files read-only, a shell command that writes to them is stopped, and each hook checks a signed manifest of its own files before it runs.

Changing that code, or turning a protection off, needs you in person: Touch ID, Windows Hello, an authenticator code, or a typed confirmation at a terminal.

Single-use permits for risky actions

Optional tokens for 15 actions, including push, publish, file writes and network fetches. You create one in a terminal; it is bound to one action and one target, expires in minutes and works once.

File and network access through brokers

Reading disk, fetching a web page and writing a file each go through one narrow agent with one tool. Some paths are never written even with approval, such as ~/.ssh, .env files, .git and shell start-up files. Credential-shaped text is withheld from what Claude reads.

Spend less of your allowance

One token profile sets seven cost settings at once. A cache-expiry guard can compact an idle session while its prompt cache is still warm. A models page shows each agent's model, effort and estimated cost.

Offline help that shows each command running

/gt:gt-help opens one local page. A simulated terminal plays each command and workflow, and a Security tab lets you try an action at each level and see whether Claude would ask.

Wrong facts can be retracted

/gt:gt-forget finds every note that states a fact that turned out to be wrong and retracts it. Notes are ranked by when they were last used, so stale ones sink without being deleted.

Handoffs close item by item

A handoff between sessions closes only when each open item is resolved: done, turned into a task, or dropped with a reason. Each one gets a stable id that tasks and notes can cite.

Breaking: /gt:gt-close now closes the session and /gt:gt-complete completes a project, task or handoff; the levels very secure, mostly secure and partly secure are now strict, trust local and trust network, and an existing setting carries over. The full list is in the changelog.

Try it

Install

git clone https://github.com/shaven/golden-thread
bash golden-thread/golden-thread-plugin/install.sh --vault ~/MyVault
# then restart Claude Code: plugins and hooks load at session start

macOS, Linux and Windows. Upgrading is the same command. Nothing is pushed or published on your behalf.
